# 海报生成工作流 - ComfyUI 资源集合

本目录包含用于海报自动化生成和文字叠加功能的 ComfyUI 工作流文件及自定义节点实现。

> **注意**: 这些文件为演示/学习副本，仅供学习和参考使用。

## 文件概览

### FL Text Overlay 节点实现

两个版本的 FL TextOverlay 节点采用不同算法：

#### FL_TextOverlay_Basic.py（基础版）
- **来源**: `comfyui_fill-nodes/nodes/vfx/FL_TextOverlay.py`
- **坐标系统**: 基于百分比的定位（0-100%）
- **功能特性**:
  - 简单的文字叠加功能，支持9点锚点系统
  - 基础字体颜色控制（RGB）
  - 直接支持 PIL 锚点参数
  - 约140行代码
- **适用场景**: 快速简单的文字叠加任务

#### FL_TextOverlay_Enhanced.py（增强版）
- **来源**: `comfyui_fill-nodes/nodes/FL_TextOverlay.py`
- **坐标系统**: 基于像素的定位
- **高级功能**:
  - 文字描边/轮廓 - 支持浮点型描边宽度
  - 渐变色文字 - 水平、垂直和对角线渐变模式
  - 自动换行 - 智能文本折行
  - 自适应字体大小 - 根据画布自动缩放字体
  - 增强的边界检查 - 多级安全边距
  - 约558行代码
- **适用场景**: 专业海报设计，需要高级排版效果

### 关键算法差异

| 特性 | 基础版 | 增强版 |
|------|--------|--------|
| 定位方式 | 百分比 (0-100%) | 像素值 |
| 文字渲染 | 单色 + 锚点 | 单色 / 描边 / 渐变 |
| 字体管理 | 固定大小 | 自适应缩放 |
| 文本处理 | 原样显示 | 自动换行 |
| 复杂度 | O(n) 线性渲染 | O(n×m) 多重采样 + 插值 |

## 研究报告：海报自动化框架

### 系统架构概述

本研究提出了一种基于知识增强语言模型与 ComfyUI 节点式工作流的**分层解耦海报自动化生成系统**。系统采用三层架构设计：

| 架构层级 | 核心技术 | 主要功能 |
|---------|---------|---------|
| **规划层** | 知识增强语言模型 (Qwen3-4b) | 需求解析 → 输出结构化设计参数 |
| **执行层** | ComfyUI + SDXL + 定制节点 | 海报背景自动化生成与文字叠加 |
| **交互层** | Vue.js + Node.js | 模板选择、参数输入、结果展示 |

### 核心工作流管线（6步）

系统实现了**"输入 → 规划 → 生成 → 合成 → 展示"**的完整流程：

#### 第1步：用户输入
- 用户在交互系统中输入海报主题、宣传目的或自然语言描述
- 可选择模板、风格或附加参数

#### 第2步：知识增强LLM规划模块（核心创新）
**这是框架的关键创新点：**

- **RAG（检索增强生成）**:
  - 构建了包含50条专业规则的**结构化设计知识库**，分为5大类：
    - 风格匹配类（15条规则）
    - 色彩搭配类（12条规则）
    - 版式设计类（10条规则）
    - 字体选取类（8条规则）
    - 设计禁用类（5条规则）
  - 采用**关键词匹配加权线性检索算法**（无需向量数据库）
  - 每条规则包含：ID、分类、触发关键词（3-8个中文关键词）、规则内容（<100字）、权重系数
  - 根据用户输入检索出最相关的Top-3条设计规则

  > ⚠️ **重要实现说明**: 本目录提供的工作流 JSON 文件**不包含预构建的知识库**。RAG 知识库必须由用户**手动创建和配置**。不过实现过程相对简单：
  >
  > - **知识库格式**: 简单的 JSON 结构，包含50条规则（可从较少开始，如10-20条核心规则）
  > - **规则结构**: 每条规则只需包含：`id`、`category`、`keywords[]`、`content`（字符串）、`weight`（数字）
  > - **存储位置**: 放置在 `ComfyUI/custom_nodes/comfyui_llm_party/file/` 目录下，支持 `.json`、`.txt` 或 `.csv` 格式
  > - **检索算法**: 轻量级的关键词线性匹配 - 无需复杂的嵌入模型或向量数据库
  > - **易于定制**: 用户可根据自己的设计偏好和行业需求添加领域特定规则
  >
  > **入门建议**: 您可以从10-15条基础设计规则开始，覆盖常见场景（科技风、毕业展、商业宣传等），然后逐步扩展。即使初始规则集较小，系统也能正常工作。

- **CoT（链式思维）推理**:
  - 将检索到的设计规则注入到 LLM 的系统提示词中作为硬性约束
  - 强制模型遵循**4步推理流程**：
    1. **需求分析**: 明确核心主题、风格定位、目标受众、关键词
    2. **版式决策**: 选择构图类型，确定主标题/副标题放置区域
    3. **色彩与字体决策**: 确定 RGB 色值、字体族、字号并说明决策依据
    4. **图像提示词生成**: 为 SDXL 生成正向提示词和负向提示词

- **结构化输出**: 模型以 JSON 格式输出：
  ```json
  {
    "title": "主标题",
    "subtitle": "副标题",
    "prompt_positive": "SDXL英文提示词...",
    "prompt_negative": "负向约束...",
    "text_position": {"title_x": 120, "title_y": 150, ...},
    "font_size": {"title": 72, "subtitle": 36},
    "font_color": {"title": [255,255,255], "subtitle": [220,240,255]},
    "font_family": {"title": "SourceHanSansCN-Bold", "subtitle": "..."}
  }
  ```

**核心优势**: 解决了通用大语言模型缺乏专业设计知识、输出非结构化/不可用参数的问题。

#### 第3步：SDXL背景图像生成
- 接收规划模块输出的结构化提示词
- 使用 **Stable Diffusion XL (SDXL)** 模型进行高质量背景生成
- 应用**正负提示词约束**来控制视觉风格
- K采样器节点处理迭代渲染
- **目标**: 生成主题一致的视觉背景（而非包含完整文字排版的最终海报）

**低显存硬件优化（4GB）**:
- 降低图像分辨率
- 启用部分参数量化
- 必要时可回退到 SD1.5 模型（质量较低但在4GB显存上更稳定）

#### 第4步：基于YOLO的禁区检测
- 使用 **YOLOv8 SEG（分割）模型**识别生成图像中的主要主体
- 将主体区域转换为**文字布局禁区**
- 防止文字遮挡重要的视觉元素
- 输出：遮罩 + XY坐标范围的禁区

> ⚠️ **实践限制与手动调整要求**:
>
> 虽然 YOLO 主体检测提供了自动禁区生成功能，但**在实际应用中识别准确率并非总是完美**。用户应注意以下局限性：
>
> - **检测不一致性**: YOLO 可能无法识别某些主体（尤其是抽象艺术元素、复杂构图或特殊对象），导致禁区不完整或不准确
> - **过度/不足分割**: 模型可能标记过大的区域（过于保守，限制文字放置选项）或过小的区域（对关键元素保护不足）
> - **风格依赖性能**: 对写实照片效果较好，但对海报设计中常见的超现实、高度风格化或重度处理的 artwork 可能表现不佳
> - **边缘情况**: 重叠对象、低对比度主体或相似背景色会干扰分割算法
>
> **推荐工作流程**:
> 1. **初始自动检测**: 让 YOLO 生成初始禁区遮罩
> 2. **视觉审查**: 始终预览生成的遮罩叠加效果以检查准确性
> 3. **手动调整**: 使用 ComfyUI 的可视化工具或坐标参数：
>    - 按需扩展/缩小禁区
>    - 为遗漏的主体添加手动排除区域
>    - 移除不必要阻止文字放置的误报区域
> 4. **迭代优化**: 如果文字仍与重要元素重叠，手动调整工作流参数中的 `text_position` 坐标
>
> **建议**: 对于关键生产工作，建议结合 YOLO 自动检测与人工审核步骤。系统提供坐标，但通常需要人工判断才能获得最佳结果。

**已考虑但未采用的替代方案**:
- Qwen3-VL-4b（多模态LLM）: 具有视觉能力但 Base64 编码显著增加 token 开销，导致延迟和上下文长度溢出错误
- 云端 API: 高网络依赖性、隐私风险、部署成本高

**最终选择**: 仅使用 Qwen3-4b（纯文本）以确保稳定性；依赖 YOLO 进行视觉理解（需人工监督）

#### 第5步：定制文字叠加节点 (FL_TextOverlay)
- **接收输入**: 背景图像 + 文本内容 + 位置坐标 + 颜色/字体/字号参数
- **执行操作**:
  - 根据标题长度和区域宽度自动换行
  - 边界检查防止文字溢出
  - 描边/轮廓渲染以提高可读性
  - 渐变色支持（水平/垂直/对角线）
  - 自适应字体大小以适配画布
- **输出**: 最终合成海报图像

**为何不在 SD 中直接生成文字？**
- SD/SDXL 模型的**中文文字生成质量差**
- 常见问题：字符畸形、拼写错误、笔画结构崩坏
- FLUX 模型改善了文字渲染但需要高显存 (>8GB)，不适合本地4GB部署
- **解决方案**: 分离背景生成与文字渲染（解耦策略）

#### 第6步：前端展示与管理
- 在浏览器界面中可视化最终海报结果
- 支持：
  - 结果预览（灯箱模式）
  - 一键下载
  - 模板继续编辑
  - 历史记录管理（LocalStorage）

### 本框架解决的问题

#### ✅ **问题1：通用LLM输出非结构化设计参数**
- **问题**: 通用大语言模型输出模糊、不可执行的描述，缺乏具体参数
- **解决方案**: RAG 知识库 + CoT 结构化推理强制输出量化、可执行的参数
- **影响**: 下游模块可直接执行，无需人工调整参数

#### ✅ **问题2：扩散模型中文文字渲染质量差**
- **问题**: SD/SDXL 生成畸变、难以辨认的中文字符
- **解决方案**: 解耦架构 - 先生成背景图像，再使用基于 PIL 的自定义节点叠加文字
- **影响**: 确保最终海报中的中文文字100%准确、清晰可读

#### ✅ **问题3：硬件门槛过高**
- **问题**: 大多数 AI 海报工具需要 8GB+ 显存或云端 API 访问
- **解决方案**:
  - 使用轻量级 Qwen3-4b 模型（可在4GB显存上运行）
  - 线性 RAG 检索（无需嵌入模型/向量数据库）
  - 优化的 SDXL 推理，支持量化
  - 必要时回退到 SD1.5
- **影响**: 支持在消费级 GPU（RTX 3050 Ti）上本地部署

#### ✅ **问题4：缺乏专业设计知识**
- **问题**: 通用 AI 工具忽略设计原则（排版、字体、色彩理论）
- **解决方案**: 包含50条规则的结构化知识库，涵盖行业最佳实践
- **影响**: 生成的海报自动遵循专业设计标准

#### ✅ **问题5：文字遮挡主体**
- **问题**: 叠加的文字可能遮挡生成图像中的重要视觉元素
- **解决方案**: 基于 YOLO 的主体检测创建禁区，实现智能布局避让
- **影响**: 保持视觉层次和可读性

#### ✅ **问题6：隐私与数据安全顾虑**
- **问题**: 云端解决方案存在数据泄露风险
- **解决方案**: 完全本地执行 - 所有数据存储在本地，无云端传输
- **影响**: 适用于敏感应用场景（学术研究、内部企业使用）

#### ✅ **问题7：生产周期长且成本高**
- **问题**: 传统手工海报设计速度慢、成本高
- **解决方案**: 从自然语言输入到最终海报的端到端自动化，秒级完成
- **影响**: 将设计时间从数小时/天缩短至分钟；成本降至接近零

## 技术细节

### 渐变色算法（增强版）
增强版实现了逐像素/逐字符的颜色插值：
- 使用 `_interpolate_color()` 方法在起始颜色和结束颜色之间进行线性插值
- 支持三种渐变模式：水平、垂直和对角线
- 采样间隔：2像素，优化性能

### 描边渲染算法
- 使用距离计算进行圆形范围检测：`distance_squared = dx*dx + dy*dy`
- 支持浮点型描边宽度，通过整数边界扩展实现
- 两遍渲染：先绘制描边层，再绘制填充层

### 自适应字体缩放
- 迭代字体缩减算法（每次迭代减少5%）
- 在边界计算中考虑描边边距
- 回退机制：失败时默认使用 PIL 内置字体

## 使用说明

1. **字体依赖**:
   - 基础版使用 `ROOT_FONTS` 目录下的本地字体
   - 增强版支持通过 `FL_USE_SYSTEM_FONTS` 环境变量使用系统字体

2. **兼容性**:
   - 需要 PIL/Pillow 库
   - 增强版需要 matplotlib 进行系统字体解析
   - 已在 ComfyUI 自定义节点生态中测试

3. **性能考虑**:
   - 基础版：执行速度快，适合批量处理
   - 增强版：由于多重采样，计算密集度更高
